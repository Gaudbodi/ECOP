<objective>
Add defense-in-depth frontend role gating to the Manual Entry create flow.
TabNav already HIDES the Manual Entry tab for validators (TabNav.tsx:23), but
the `ManualEntry` component itself is not role-guarded if reached directly, and
`App.tsx` does not pass `user` into it. Pass `user` from `App.tsx` into
`ManualEntry` (same prop convention already used for Pipeline/Settings), then
add a role gate at the top of `ManualEntry` that renders a clean permission-denied
empty state for non-creator roles. This is UX/defense-in-depth only — the real
boundary is the server gate in Plan 11-01.

Purpose: CONTEXT.md asks for BOTH layers (server enforcement AND frontend gating).
This plan delivers the second layer consistently with the codebase's established
hide-on-deny idiom (ValidatorControls/LifecycleControls `return`-a-gate pattern),
not disable-with-tooltip (which has no precedent here).
Output: A role-gated ManualEntry that shows the create form only to
generators/admins/super-admins.
</objective>
