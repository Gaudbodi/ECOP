<objective>
Close the single load-bearing backend gap in the role matrix: `manual_alert`
(ghana_cap_app.py:384-402) has `@login_required` but NO role check, so a
`cap validator` can currently POST a create and — because the stage ternary is
`1 if role=='cap generator' else 3` — would get an alert dispatched at stage 3.
This violates the LOCKED matrix ("validators cannot create"). Add the server-side
create-role gate, then verify (do not change) the other three role/stage sync
points CLAUDE.md requires to stay coherent. Add pytest coverage for the create,
validate, AND lifecycle role gates.

Purpose: Server-side enforcement is the security boundary — frontend gating
(Plan 11-02) is UX only and cannot be trusted. This plan makes the API honor the
LOCKED role matrix.
Output: A role-gated `manual_alert` endpoint and five new endpoint tests proving
the create + validate + lifecycle matrix rows.
</objective>
